# CONTEXT — Bring Dimitrii To Home: Luperon

Онбординг-контекст проекта: что это, на чём, какие ключевые решения приняты
и почему. Читается первым при входе в проект (в т.ч. в сессии разработки).

## Суть игры

2D-симулятор динги — небольшой надувной лодки, на которой экипаж
перемещается от яхты к берегу (доку) и обратно. Помимо перемещения из точки
А в точку Б по воде и объезда препятствий (другие лодки, корабли, яхты —
статичные и движущиеся), ключевая механика — **буксировка**: цеплять тросом
другую динги (без мотора или со сломанным) и доводить её до места назначения
(яхты её владельца).

Каждая "версия" игры — отдельный самодостаточный мир. Текущая версия целиком
базируется в заливе **Luperón**, с возможным частичным выходом героя в
прибрежную зону (док, прибрежный ресторан).

## Платформы

- Цель: мобильные — **Android и iOS**, из одной кодовой базы.
- Разработка и отладка desktop/Android ведутся на Windows.
- iOS — отдельная финальная стадия: сборка/подпись требуют macOS + Xcode
  (с Windows не собирается). На логику проекта это не влияет.

## Технологический стек

- Движок: **Godot 4.7** (установлена 4.7.2), сборка GDScript.
- Рендерер: **Compatibility** (OpenGL3 / D3D11) — достаточно для 2D и шире
  по совместимости с бюджетными Android-устройствами.
- Язык: **GDScript** со статической типизацией (аннотации типов). При
  необходимости более жёсткой типизации возможен переход на C# (.NET-сборка).
- Физика: встроенный 2D-движок Godot; трос — свой, на GDScript (GDExtension
  не нужен).

## Ключевые решения (журнал)

- **Движок — Godot, не Unity.** Критерии: безусловная бесплатность (MIT, без
  порога выручки и роялти), git-дружелюбность (текстовые сцены `.tscn`),
  модель "сцена = версия игры" ложится на узловую архитектуру Godot.
- **2D, рендерер Compatibility** — тип игры не требует 3D/Forward+.
- **Физическая модель лодки** — `RigidBody2D` без гравитации
  (`gravity_scale = 0`). "Вода": линейное сопротивление раздельно вдоль и
  поперёк корпуса (поперечное в разы выше — "киль"; без этого лодка скользит
  боком, а буксируемая не выстраивается за буксиром), вращение гасит
  `angular_damp`. Тяга вдоль носа, руль эффективен пропорционально скорости.
- **Строгая типизация GDScript** — предупреждения о нетипизированных
  объявлениях и небезопасном доступе подняты до ошибок (`project.godot`
  `[debug]`); CI падает на таком коде. Переход на C# пока не нужен.
- **Трос-буксир — главный технический риск.** Решён своим тросом на
  GDScript (`TowRope`): односторонняя упругая связь (только тянет) с
  демпфированием и пределом силы. `DampedSpringJoint2D` отклонён — это
  пружина, она работает и на сжатие. Устойчивость проверена headless;
  Rapier/Box2D через GDExtension не понадобились (и не нужен Gradle Build
  для Android).
- **Ландшафт** (береговая линия, заливы, доки) — планируется на TileSet
  Terrains с автоскруглением краёв. Внутриигровой конструктор НЕ нужен.

## Среда разработки

- Редактор Godot 4.7 + VS Code с расширением godot-tools (LSP + DAP-отладка).
- Отладка: встроенный отладчик редактора; из VS Code по F5; на телефоне —
  Deploy with Remote Debug по USB.
- Android-тулчейн: OpenJDK 17, Android SDK (Platform android-35,
  Build-Tools 35.0.1, Platform-Tools, Command-line Tools), NDK 28.1.13356709,
  CMake 3.10.2.4988404. Подробности — `SETUP.md` в корне.
